# Problem Score — StepShield for Jira (Forge Automation JSON Offload Runner)

ID: `IDEA-1` · Ambition: `indie` · Active Scenario: `Scenario B` · Signals: SIG-1

## Target Market (Scenario A)
- **Buyer:** Jira Cloud Standard Administrators and IT Operations Leads at 50–250 seat organizations ($5,820–$29,100/yr base Jira Standard spend) exceeding Atlassian's pooled 400 steps/user/month Automation Usage-Based Pricing allowance by enough strictly Jira-internal steps to incur overage bills above $900–$4,500/yr.
- **Problem:** Atlassian's December 3, 2026 shift to step-based Automation Usage-Based Pricing pools 400 steps/user/mo on Jira Cloud Standard (plus Confluence/JSM pools) and bills overages at $0.50/1,000 steps by default (or halts rules if opted out). Crucially, live research disproves two claims in the pitch: Atlassian already exempted NO_ACTIONS_PERFORMED runs, logging, variables, and lookup tables from step counts, and Jira Standard teams do NOT face a forced $11,880–$29,700/yr Jira Premium upgrade wall because PAYG ($0.50/1k steps) is cheaper than StepShield up to 340k–850k billable steps/month. Only the tiny tail of heavy-burn Jira-internal automation orgs exceeds PAYG break-even, where JMWE and ScriptRunner already run unlimited Event-based and Scheduled JQL Actions outside native step limits.
- **Trade-offs:** Executes strictly Jira-internal automation rules via 1-click native JSON import on pure Forge ('Runs on Atlassian' zero-egress badge); deliberately refuses outbound Slack/Teams/webhooks, custom Groovy/JS scripting, UI field-behavior hooks, Data Center builds, and enterprise SOWs.
- **Price:** $1.50/user/month via Atlassian Marketplace standard per-user tiers (free <=10 users; $900/yr at 50 seats; $1,800/yr at 100 seats; $4,500/yr at 250 seats; ~17% annual discount; 30-day free trial via Paid via Atlassian; billing cycle forced to match host Jira subscription).
