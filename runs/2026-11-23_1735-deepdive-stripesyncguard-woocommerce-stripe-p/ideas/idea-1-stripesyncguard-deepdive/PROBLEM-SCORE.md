# Problem Score — StripeSyncGuard — WooCommerce + Stripe Payment-State Reconciler & Staging Killswitch

## Scenario A
- **Buyer:** Technical store owners / e-commerce ops leads operating a single $250k-$10M GMV WooCommerce + Stripe (or WooPayments) store running WooCommerce Subscriptions and/or Cloudflare/WP Rocket caching layers (unblended from the pitch's separate 2-25 staff agency buyer persona per asb-problem no-blending rule).
- **Problem:** Aggressive Cloudflare/WAF/WP Rocket caching layers silently intercept Stripe POST webhooks (/wc-api/wc_stripe) and return cached 200 HTML or 4xx blocks, leaving customers charged in Stripe while WooCommerce orders stay in Pending Payment; simultaneously, Action Scheduler queues stall under WP-Cron or PHP timeouts and drop WooCommerce Subscriptions renewals, and staging clones with live Stripe keys risk firing accidental live charges or desyncing customer payment tokens.
- **Trade-offs:** WooCommerce + Stripe / WooCommerce Subscriptions payment-state integrity and staging live-charge killswitch only — deliberately excludes generic WordPress backups, uptime pings, malware scanning, plugin auto-updates, analytics/email automation (Metorik), payment gateway replacement, and blind auto-refunds.
- **Price:** $49/mo ($588/yr) single-store plan (up to 5,000 orders/renewals) — unblended from the separate $149/$299/mo multi-client agency plans (More for More)
