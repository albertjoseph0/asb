## Root-Cause Persistence
- The Vanta/Drata Supabase RLS inspection gap persists NOT because incumbents have a structural business-model conflict leaving a lucrative indie market unserved (DP4), but because standalone commercial demand for a paid RLS evidence-sync wrapper is structurally compressed to near zero from three sides: (1) Zero-cost native + OSS primitives already satisfy the CI-evidence checkbox — Supabase natively ships Security Advisor, `supabase db lint`, and `supabase test db` (pgTAP), MIT SupaShield (`Rodrigotari1/supashield`) and `supabase-test-suite` execute role-based RLS assertions in CI with JSON output, and pushing CI artifacts to Vanta (`POST /v1/documents/{documentId}/uploads`) or Drata (`drata/compliance-as-code-action` / Evidence Library API) takes a ~20-line GitHub Action (DP11); (2) SOC 2 Type II auditors (CC6.1/CC6.3) explicitly require third-party manual penetration tests ($6k-$25k) for logical multi-tenant isolation and treat CI test runs only as supplementary operational evidence that raw GitHub Actions logs already satisfy, preventing PolicyGate from replacing pentest budget or commanding $10k/yr ACV (DP10); and (3) Active Postgres-RLS + SOC 2 Type II + 5-30 engineer B2B SaaS is a tiny (~1,500-3,000 global accounts), annually purchased (`Liquid = 0.1`) cohort whose weak organic pull is corroborated by minimal GitHub traction on free OSS RLS testers (`pgrls` 29 stars, `rlsautotest` 26 stars). *(Indie-favorable: `False`)*

## 1st / 2nd / 3rd-Order Consequences
### First-Order
- Free OSS cannibalization of the paid tier: open-sourcing the MIT GitHub Action runner (required to clear Eager-Identity credential-egress fears) hands technically capable 5-30 engineer teams the exact execution engine for $0; CTOs and staff engineers can run free native `supabase test db` (pgTAP) or MIT SupaShield and wire a ~20-line GitHub Action to Vanta's `POST /v1/documents/{documentId}/uploads` or Drata's `drata/compliance-as-code-action` / Evidence Library API rather than paying $2,388/yr for signed-bundle sync (DP11).
- Tiny, illiquid top-of-funnel: narrowing to 5-30 engineer multi-tenant Postgres/Supabase B2B SaaS teams using active Postgres RLS AND maintaining SOC 2 Type II on Vanta/Drata caps qualified accounts at ~1,500-3,000 globally (`Plausible = 1,000`, DP14), while annual compliance renewal cycles pin buying liquidity at `Liquid = 0.1` (DP9), starving self-serve monthly acquisition.
- Price compression from both floor and ceiling (DP8): trapped between $0 native Supabase CLI (`supabase db lint` + `supabase test db`) / MIT SupaShield, $29-$49/mo Vibe App Scanner, $499/yr MigrationPilot Org, and $49-$149/mo Kihtey below — and mandatory $6k-$25k human pen tests plus $10k-$20k/yr Vanta/Drata contracts above — PolicyGate cannot displace pentest budgets or push ACV toward the $10,000/yr tier required to make a 1,000-account niche viable (DP14, DP16).

### Second-Order
- Audit-window churn ("pass-and-cancel" economics): cash-conscious 5-30 engineer CTOs buy compliance utilities under pre-audit deadline stress, obtain their SOC 2 Type II report (and discover their CPA auditor accepts standard GitHub Actions pgTAP run logs alongside the mandatory manual pen test), then cancel before year-two renewal — collapsing realized LTV well below $2,388/yr.
- High-touch custom-schema support drag: real-world multi-tenant Postgres RLS architectures rely on heterogeneous JWT claims, `SET LOCAL` session variables, recursive role graphs, `SECURITY DEFINER` RPCs, and storage bucket policies; diagnosing false positives and false negatives across bespoke customer schemas turns a $199/mo self-serve SaaS into low-margin security-engineering support for a solo founder.
- Liability-creep and vendor-review friction: if a paying customer suffers a cross-tenant data leak through a `SECURITY DEFINER` function, service-role query, or untested RPC path after PolicyGate emits a signed green evidence bundle, buyers blame the tool and demand institutional assurances/indemnity an unvetted indie founder cannot supply (DP10), while security-conscious CTOs hesitate to grant an unknown solo vendor OAuth write access into their Vanta/Drata compliance workspace.

### Third-Order
- Host-platform absorption from both ends of the bridge (DP11): Supabase ($599/mo Team compliance tier, native Security Advisor, `supabase db lint`, and `supabase test db`) and Vanta/Drata ($10k-$45k/yr ACV, existing native GitHub/CI compliance apps like `drata/compliance-as-code-action`) have zero business-model conflict against adding a native "Supabase Security Advisor + CI pgTAP pass-rate" check or one-click compliance export, obsoleting a standalone $199/mo glue SaaS within 12-24 months.
- AI coding agents erode the "brittle pgTAP maintenance" wedge: the same frontier coding agents (Claude Code, Cursor, Codex) that motivated Scenario A's RLS-bug concern increasingly auto-generate and update pgTAP or Jest cross-tenant isolation tests inline on every migration PR via free repo prompts/skills, reducing PolicyGate's test-authoring convenience to a $0 commodity.
- Up-market architectural graduation away from pure Postgres RLS: as multi-tenant B2B SaaS teams outgrow early Supabase prototypes into complex enterprise RBAC/ABAC, many migrate authorization enforcement to application-layer policy engines or schema/database-per-tenant isolation rather than deepening raw SQL RLS policies — steadily shrinking the highest-LTV segment of the addressable pool.
